# Задание 1. Исследование моделей и инфраструктуры

## 1. Сравнение LLM-моделей

| Критерий                               | Локальные Hugging Face                                  | Облачные OpenAI/YandexGPT                                  |
|----------------------------------------|---------------------------------------------------------|------------------------------------------------------------|
| **Качество ответов**                   | Хорошее для многих задач, зависит от модели.            | Очень высокое. YandexGPT хорошо работает с русским языком. |
| **Скорость работы**                    | Зависит от GPU. На CPU - медленно.                      | Очень высокая (при хорошем качестве сети).                 |
| **Стоимость владения и исаользования** | Высокие затраты на GPU-сервер. Нет оплаты за токен.     | Оплата за токены. Дорого при интенсивном использовании.    |
| **Удобство и простота развёртывания**  | Сложно: нужно подбирать зависимости, API-обёртку и т.д. | Очень просто: API-ключ и использование API-запросов.       |

## 2. Сравнение моделей эмбеддингов

| Критерий                               | Локальные Sentence‑Transformers | Облачные OpenAI/Yandex Embeddings           |
|----------------------------------------|---------------------------------|---------------------------------------------|
| **Скорость создания индекса**          | Медленно, зависит от CPU.       | Быстро (высокая пропускная способность API) |
| **Качество поиска**                    | Хорошее.                        | Отличное.                                   |
| **Стоимость владения и использования** | Бесплатно.                      | Оплата за каждый токен, зависит от тарифа.  |

## 3. Сравнение векторных баз ChromaDB и FAISS

| Критерий                            | ChromaDB                                             | FAISS                                                                 |
|-------------------------------------|------------------------------------------------------|-----------------------------------------------------------------------|
| **Скорость поиска**                 | Средняя (подходит для <1M векторов)                  | Очень высокая (оптимизирован для >1M)                                 |
| **Скорость индексации**             | Простая, но может тормозить на больших данных        | Быстрая, поддерживает batch-добавление                                |
| **Сложность внедрения и поддержки** | Низкая - всё в одном (сохранение, эмбеддинги, поиск) | Средняя - требует ручного управления индексами                        |
| **Удобство в работе**               | Высокое, удобное API                                 | Хорошее, но необходимо дополнительно реализовывать необходимую логику |
| **Стоимость владения**              | Низкая (in‑memory, но можно сохранять на диск)       | Низкая (только RAM/диск)                                              |

## 4. Рекомендуемая конфигурация сервера

Для локального RAG-бота с FAISS + Sentence‑Transformers + локальная модель:

- **CPU:** 4-8 ядер
- **RAM:** 32–64 ГБ
- **GPU:** NVIDIA RTX 3090/4090 с 24 ГБ VRAM (ускоряет LLM и эмбеддинги)

## Итоговые рекомендации

| Вариант                       | LLM                | Эмбеддинги            | Векторная БД | Инфраструктура        | Плюсы                              | Минусы                                 |
|-------------------------------|--------------------|-----------------------|--------------|-----------------------|------------------------------------|----------------------------------------|
| **1. Облачный быстрый**       | YandexGPT          | Yandex Embeddings     | ChromaDB     | Облако (Yandex Cloud) | Простота, скорость, нет GPU        | Расходы на API, данные уходят в облако |
| **2. Локальный экономичный**  | Llama 3 8B         | Sentence‑Transformers | FAISS        | CPU + 32ГБ RAM        | Нет затрат на API, данные локально | Медленнее, сложнее настройка           |
| **3. Гибридный**              | Облачный YandexGPT | Локальный e5          | FAISS        | CPU + облако          | Баланс качества и безопасности     | Сложнее поддерживать                   |
| **4. Высокопроизводительный** | Llama 3 70B        | OpenAI                | FAISS        | Облачный GPU-сервер   | Макс. качество                     | Дорого                                 |

**Лучший для большинства компаний с конфиденциальными данными:**  
**Вариант 2 (локальный + ChromaDB)** - безопасность, отсутствие затрат на API, приемлемая скорость.

**Лучший для скорости и качества при некритичных данных:**  
**Вариант 1 (YandexGPT + Yandex Embeddings + FAISS)**.

## Выбор для бота

Я планирую использовать **all-MiniLM-L6-v2** для эмбеддингов, локальную **ollama** в качестве LLM и векторную БД **FAISS**.

**FAISS** потому что:

- Высокая скорость поиска (даже на CPU).
- Надёжная работа с большим количеством документов (>10k).
- Не требует дополнительной инфраструктуры (всё в памяти/на диске).

**Почему не ChromaDB:** она удобнее для прототипов, но FAISS даёт лучшую производительность для продуктивного бота,
особенно при масштабировании.
